## I.2 CLI delta v0.5.21 → v0.7.0-rc.18

### I.2.1 New top-level commands (v0.6.9, "npm-style project experience")

- `animus install [--locked] [--force] [--allow-org OWNER…]` — resolves `animus.toml` → `.animus/plugins.lock`, installs plugins + packs. `--locked` = npm-ci semantics: reproduces the committed lock exactly, fails on manifest↔lock drift. Clap defs: `crates/orchestrator-cli/src/cli_types/manifest_types.rs`.
- `animus add <SPEC> [--pack] [--path PATH] [--force]` — SPEC forms: `name[@version]`, `OWNER/REPO[@tag]`, bare `name`. Mutates `animus.toml` + installs.
- `animus remove <NAME> [--pack]` — drops from manifest + uninstalls.
- `animus init` (extended): now also scaffolds `animus.toml`, `.env.example`, merge-safe project `.gitignore`. Team onboarding story: **`git clone && animus install`** (CI/Docker: `animus install --locked`).
- `.env` → secrets sync: `animus install` provisions secrets from `.env` into the device-encrypted store (idempotent; blank `KEY=` skipped, never stored empty; imports audited) and warns about keys declared in `.env.example` but unset.

### I.2.2 avm (v0.6.11)

### I.2.5 Plugin system

- **Model inversion:** `animus.toml` = declared intent; `.animus/plugins.lock` = **source of truth**; `plugins.yaml` = **derived projection regenerated on every mutating op** (never hand-edit, never commit as authority — it heals from the lock). (v0.6.9)
- **Lock schema 2.0** (0.6.7): per-target-triple integrity — `targets: {triple → {archive_sha256, signature_bundle_sha256, installed_binary_sha256}}`; install records shas for EVERY published platform from `SHA256SUMS.txt`, so a macOS-generated lock drives verified linux `--locked` installs. 1.0 locks migrate with empty targets (re-install to upgrade).
- **Signature policy, context-aware** (rc.1): precedence = per-call `--signature-policy` flag > `ANIMUS_PLUGIN_SIGNATURE_POLICY` env (`strict|warn|skip`) > `plugins.signature_policy` global config > `warn` default.
- **Fail-closed TOFU** (rc.1): on non-TTY or `ANIMUS_SERVER=1`, `--yes`/`--force` will NOT auto-trust an unknown org; escape hatch `--allow-org` on install commands. Release-source gate runs BEFORE download.
- **Reserved-name policy** (0.6.10): canonical `animus-provider-<reserved>` (claude/codex/gemini/opencode/oai/oai-agent/oai-runner) from trusted publisher `launchapp-dev` installs with **NO flag**; only untrusted orgs and `--path`/`--url` installs need `--allow-shadow-builtin`.
- **Multi-kind plugins** (rc.1): manifests declare `plugin_kinds` + `kind_capabilities`; all role resolvers use `serves_kind`/`discover_by_kind` (rc.9) — one consolidated plugin (e.g. `animus-postgres`) can serve many roles.
- **Discovery hardening** (rc.1): project-local `plugins.yaml` `binary:` entries and project-local dir scans gated by trust/location; server-safe `discover_plugins` never executes repo-shipped binaries.
- **DB-registry discovery tier** (rc.3): opt-in tier resolving the plugin set from a Postgres `plugin_registry` (animus-postgres BaaS); after explicit/project tiers, before global-dir scan.
- **noarch target** (rc.3): `<name>-noarch.tar.gz` fallback asset.
- **`supports_mcp` manifest field** (rc.7→rc.9): MCP-server injection driven by the provider plugin's declared `supports_mcp` (protocol 1.2.0; undeclared defaults true).
- Plugin runtime cap (0.6.6): daemon injects `TOKIO_WORKER_THREADS=2` into every spawned plugin + runner subprocess.
- Protocol crates moved to `launchapp-dev/animus-protocol` (0.6.1); in-tree `animus-plugin-protocol` dropped in v0.7.
- Default flavor now requires `[config_source] launchapp-dev/animus-config-yaml`; recommended codex provider is `animus-provider-codex-mcp`.

Claude-only; kill-switch `ANIMUS_DISABLE_HARNESS_HOOKS`.

### I.3.6 `models:`, `worktree:`, misc sections

### I.3.7 `budget:` (workflow, rich-phase, daemon)

`max_tokens` (u64 >0), `max_cost_usd` (finite >0) — at least one required; `on_exceed: pause|fail|warn` (default pause). Workflow cap subsumes phase caps; phase budget resets per rework attempt.
